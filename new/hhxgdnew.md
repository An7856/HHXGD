# 黑湖小工单旗舰版 从0到1完整操作手册（5.5按摩弹力球案例）

> **适用版本**：黑湖小工单旗舰版（含销售管理、采购管理、委外管理）
> **工厂类型**：TPE/TPR软胶玩具、弹力球等生产工厂
> **产品案例**：5.5按摩弹力球（35箱订单）
> **核心模式**：报工即扣料——工人报工提交数量的那一刻，系统自动完成产量统计、物料库存自动扣减、计件工资自动累积
> **工单生成机制**：销售订单通过「履约助手」→「安排生产」触发系统自动展开BOM，工单数量 = 销售订单数量 × BOM单位用量
> **目标读者**：系统管理员、生产主管、计划员、采购员、销售员、仓库、财务

## 第一部分：系统认知与核心逻辑

### 一、工单数量计算规则（核心）
**工单数量 = 销售订单数量 × BOM中该子件的单位用量**

以5.5按摩弹力球为例：
- 销售订单：35箱
- 每箱装24个白盒，每个白盒装12个球，共10,080个球
- BOM中“白盒”的单位用量 = 24个/箱
- 系统自动生成工单：35箱 × 24个/箱 = 840个白盒工单
- BOM中“普通红蓝灯”的单位用量 = 1个/球
- 系统自动生成工单：35箱 × 288个球/箱 × 1个灯/球 = 10,080个灯工单

> ⚠️ **关键理解**：销售订单填的是“成品箱数”（35箱），子工单数量由BOM中的“单位用量”自动计算得出。不是必须把销售订单改成10,080，而是确保BOM里的单位用量设置正确。

### 二、系统核心逻辑
销售订单通过「履约助手」→「安排生产」触发系统自动展开BOM，根据BOM单位用量自动计算所有子件的需求数量，一键生成全部半成品和成品工单。

## 第二部分：核心概念详解（单位用量 vs 报工数配比）

### 一、单位用量（BOM里的概念）

**一句话理解：单位用量 = 每生产1个成品，需要消耗多少个该物料。**

| 场景 | 单位用量 | 含义 |
| :--- | :--- | :--- |
| 每箱装24个白盒 | 24 | 每生产1箱成品，需要消耗24个白盒 |
| 每盒装12个球 | 12 | 每生产1个白盒，需要消耗12个球 |
| 每个球装1个灯 | 1 | 每生产1个球，需要消耗1个灯 |

**单位用量的作用是：计算“总共需要多少物料”。**

系统计算公式：**物料总需求 = 销售订单数量 × 单位用量**

举例：
- 销售订单35箱，白盒单位用量=24
- 白盒总需求 = 35 × 24 = 840个
- 这个840，就是采购需求，也是生产工单的计划数

### 二、报工数配比（工序里的概念）

**一句话理解：报工数配比 = 工人报多少个，系统算作1个产出单位。**

| 场景 | 报工数配比 | 含义 |
| :--- | :--- | :--- |
| 每12个球装1个白盒 | 12 | 工人每报12个球，系统记1个白盒 |
| 每24个白盒装1箱 | 24 | 工人每报24个白盒，系统记1箱 |
| 每个球装1个灯 | 1 | 工人报1个灯，系统记1个 |

**报工数配比的作用是：把工人按“个”报的数字，换算成系统按“箱/盒”计算的进度。**

系统计算公式：**系统产出 = 工人报工数量 ÷ 报工数配比**

举例：
- 工人装了120个球（每12个球装1个白盒）
- 报工数配比 = 12
- 系统产出 = 120 ÷ 12 = 10个白盒

### 三、两者的关系

| 对比 | 单位用量 | 报工数配比 |
| :--- | :--- | :--- |
| **位置** | BOM里，每个物料一行 | 工序里，每道工序一个值 |
| **作用** | 算“要买/做多少” | 算“做完了多少” |
| **方向** | 从成品往下算 | 从报工往上算 |
| **你的例子** | 白盒单位用量=24 | 入白盒工序配比=12 |

**举个例子串起来：**

1. **接单**：35箱订单
2. **算需求**（用单位用量）：35箱 × 24个白盒/箱 = 840个白盒，需要采购
3. **工人干活**：工人把球装进白盒，每12个球装1盒
4. **报工**（用报工数配比）：工人装了120个球，报工数配比=12，系统记10个白盒
5. **做满**：工人总共装了10,080个球，报工数配比=12，系统记840个白盒，正好等于需求
6. **装箱**（用单位用量）：840个白盒 ÷ 24个/箱 = 35箱，成品入库

## 第三部分：第一天——基础数据配置（一次性工作）

> **配置顺序**：部门 → 用户 → 单位 → 不良品项 → 客户 → 供应商 → 设备 → 工序 → 工艺路线 → 产品定义 → 物料清单 → 绩效工资 → 仓库。

### 配置前必读：核心规则

**规则一：BOM单位用量决定工单数量**
- BOM中每个子件的“单位用量”告诉系统：每生产1件成品，需要消耗多少个该子件。
- 销售订单数量 × 单位用量 = 该子件的工单生产数量。

**规则二：产品的“工艺路线”字段**
- 原材料（外购）：不填，保持空白。
- 半成品（自制）：必须填。
- 成品（自制）：必须填。

**规则三：外协工序需在工序设置中标记“委外”**

**规则四：产品属性决定采购需求**
- 外购（原材料、包材）：系统在“生成采购需求”时会自动计算这些物料的需求量。
- 自制（半成品、成品）：系统不会生成采购需求，而是生成生产工单。

### 二、什么是自定义事件？

当某个操作发生（如工人报工）时，系统自动执行另一个操作（如生成入库单或出库单）。

配置逻辑：**触发条件 + 触发动作 → 执行动作**
- **触发条件**：谁触发了这个规则？如 `${任务.工序名称} == '注塑（含拌料）'`
- **触发动作**：发生了什么操作？如“新增数据”
- **执行动作**：系统应该做什么？如“按工单用料清单生成入库记录”

> ⚠️ **关键提醒**：触发条件里的工序名称必须和系统里「基础数据」→「工序」里定义的名称完全一致。

### 三、判断用入库单还是出库单

| 场景 | 执行表单 | 举例 |
|------|----------|------|
| 该工序产出物料（库存增加） | 入库单 | 注塑产出半成品、入外箱产出成品 |
| 该工序消耗物料（库存扣减） | 出库单 | 装灯消耗灯、入白盒消耗白盒 |

## 第五部分：多车间多仓库管理（3楼/7楼包装车间）

### 一、业务场景
你有两个包装车间，分别在3楼和7楼，各自有自己的仓库。需要实现：
- 3楼工人报工，自动扣减3楼仓库的包材，成品入3楼仓库。
- 7楼工人报工，自动扣减7楼仓库的包材，成品入7楼仓库。
- 库存数据完全分开，互不影响。

### 二、为什么报工页面不能直接选仓库？
黑湖小工单采用“报工即扣料”的自动化逻辑。工人扫码报工时，系统根据**工序配置的“所属仓库”**自动决定扣哪个仓库，不需要工人在报工页面手动选择。

### 三、配置步骤

**第一步：创建两个独立仓库**
进入「基础数据」→「仓库」→「创建仓库」：3楼包装车间仓、7楼包装车间仓。

**第二步：创建两组独立包装工序**
进入「基础数据」→「工序」→「创建工序」：3楼-入白盒、3楼-入外箱、7楼-入白盒、7楼-入外箱。

**第三步：绑定所属仓库**
编辑每个工序，将“所属仓库”分别绑定到对应仓库。

**第四步：分别创建成品档案（关键）**
创建两个成品编码：FIN-BALL-3F、FIN-BALL-7F，各自配置独立的BOM和工艺路线。

**第五步：更新工艺路线**
为两个成品分别创建工艺路线：3楼成品包装、7楼成品包装。

**第六步：配置自定义事件（报工联动）**
为两个车间的包装工序分别配置自定义事件。

### 四、同一订单两个车间一起做（拆单操作）

**场景**：同一个35箱的订单，要分给3楼和7楼两个包装车间一起做，3楼做20箱，7楼做15箱。

**第一步：创建销售订单**
创建销售订单，数量填35箱，提交审批。

**第二步：在履约助手中拆单**
审批通过后，进入「履约助手」，找到该订单，点击「拆单」，按数量拆成两张工单。

**第三步：两张工单分别派工**
工单A派给3楼包装车间，工单B派给7楼包装车间。

**第四步：各自独立报工、独立入库**
- 3楼工人扫工单A的码报工，系统自动扣减3楼仓的包材，成品入3楼仓。
- 7楼工人扫工单B的码报工，系统自动扣减7楼仓的包材，成品入7楼仓。

### 五、成品编码分开是什么意思
同一个产品，如果由两个不同的车间生产，需要在系统里建两个不同的产品档案（两个编码），各自绑定各自的工序和仓库，让系统能分清谁做的、扣谁的料、入谁的仓。

## 第六部分：部分委外+部分自制的混合场景

### 一、业务场景
你接了一张1000个的订单，生产工序是：注塑→组装→喷漆→包装。
做到一半发现喷漆来不及，需要把其中**500个的喷漆工序委外**，另外500个继续本厂做。

### 二、为什么不能直接拆分原工单？
原工单的注塑、组装、包装都是本厂做1000个，只有喷漆要分500出去。如果拆原工单，会把注塑、组装、包装也一起拆成两张500个的，反而更乱。

### 三、正确操作方案

**方案：原工单不动，新建委外工单**

**第一步：原工单保持1000个不变**
注塑、组装、包装三道工序，本厂都按1000个正常做、正常报工。
喷漆工序，本厂只做500个，工人正常报工。

**第二步：新建一张委外工单**
- 进入「生产管理」→「工单」→「创建工单」
- 数量填500
- 只保留“喷漆（委外）”这一道工序
- 标记为委外，指定外协供应商

**第三步：走委外流程**
- 进入「委外管理」→「委外出库」，把500个半成品发给外协厂，库存自动扣减
- 外协厂通过微信链接接收任务、反馈进度
- 回厂后做「委外入库」，库存自动增加

**第四步：修改原工单的喷漆计划数（可选）**
如果想让原工单的喷漆进度显示正常，可以把原工单“喷漆”工序的计划数从1000改成500。
- 这样本厂喷漆工只需要报500个，喷漆工序进度就是100%
- 注塑、组装、包装三道工序的计划数还是1000，进度不受影响

### 四、进度条和核算的关系（重要）

| 项目 | 显示方式 | 核算方式 |
|------|----------|----------|
| 原工单喷漆进度 | 可能显示50%（如果不改计划数） | 本厂工资按实际报工的500个算 |
| 委外工单进度 | 100% | 外协加工费按委外单据独立算 |
| 注塑、组装、包装 | 100% | 本厂工资按1000个算 |
| 月底对账 | 两笔账分开 | 本厂工资+外协加工费，各自独立 |

**核心原则：账对，比进度条好看重要。**
- 如果为了进度条显示100%，把委外的产出硬塞进本厂工序，会歪曲计件工资和外协加工费的核算。
- 原工单喷漆工序显示50%，只是反映“本厂只做了计划量的一半”，这个数字是真实的。

### 五、操作要点总结

| 步骤 | 操作 | 系统位置 |
|------|------|----------|
| 1 | 原工单保持1000个 | 生产管理→工单 |
| 2 | 新建委外工单500个，只有喷漆工序 | 生产管理→工单→创建工单 |
| 3 | 委外出库发料500个 | 委外管理→委外出库 |
| 4 | 外协加工反馈 | 外协厂微信链接 |
| 5 | 委外入库收货500个 | 委外管理→委外入库 |
| 6 | （可选）修改原工单喷漆计划数为500 | 生产管理→工单→编辑 |
| 7 | 月底对账 | 本厂工资报表+委外对账单 |

### 六、委外与自制的账务区分

| 项目 | 本厂自制部分 | 委外部分 |
|------|-------------|----------|
| 计件工资 | 按本厂喷漆单价×500个 | 不计入本厂工资 |
| 外协加工费 | 不产生 | 按委外单据×外协单价 |
| 库存扣减 | 报工时自动扣半成品 | 委外出库时扣半成品 |
| 库存增加 | 报工时自动增加喷漆后成品 | 委外入库时增加喷漆后成品 |
| 成本核算 | 本厂加工成本 | 外协加工成本 |

1. 进入「采购管理」→「智能补货」。
2. 系统根据安全库存水位、近期消耗速度、采购提前期计算补货建议。

|----------|----------|
| 入库单 | 采购入库、生产完工入库、委外入库、其他入库 |
| 出库单 | 工单领料出库、委外出库、销售出库、其他出库 |
| 调整单 | 期初调整、盘盈盘亏、报废调整 |
| 调拨单 | 仓库间物料转移 |
| 库存报表 | 库存收发明细、库存余额、进销存汇总 |
| 多维库存明细 | 按仓库、批次、物料多维度查看库存 |

### 二、库存与生产/采购的联动机制

| 触发动作 | 系统自动完成的库存变化 |
|----------|----------------------|
| 采购收货 | 原料库存自动增加 |
| 工单报工 | 物料库存自动扣减 |
| 注塑报工 | 半成品库存自动增加 |
| 入外箱报工 | 成品库存自动增加 |
| 销售出库 | 成品库存自动扣减 |
| 委外出库 | 库存扣减，生成“委外在制库存” |
| 委外入库 | 半成品/成品库存自动增加 |

### 三、入库管理操作
采购入库、生产完工入库、委外入库，各自在对应模块操作。

### 四、出库管理操作
工单领料出库、销售出库、委外出库，各自在对应模块操作。

### 五、调拨管理操作（多仓库之间）
进入「库存管理」→「调拨单」→「新建调拨单」，选择调出仓库和调入仓库，添加物料和数量，提交后系统自动完成库存转移。

### 六、库存报表与核对

| 报表名称 | 用途 |
|----------|------|
| 库存余额明细 | 查看各类物料当前库存、仓库分布 |
| 库存收发明细 | 查看每笔库存变动的来源 |
| 进销存汇总 | 期初+入库-出库=期末库存，核对账实 |
| 多维库存明细 | 按仓库、批次、物料多维度查看 |

## 第十部分：全局关键注意事项

### 一、BOM单位用量决定工单数量
| 场景 | 正确设置 | 错误设置 | 后果 |
|------|----------|----------|------|
| 每箱含24个白盒 | 单位用量=24 | 单位用量=1 | 工单只有35个，缺料停产 |
| 每箱含1个外箱 | 单位用量=1 | 单位用量=24 | 生产多了23倍外箱 |
| 每球含1个灯 | 单位用量=1 | 单位用量=3 | 灯多采购2倍 |

### 二、工单生成的正确操作路径
| 操作方式 | 结果 | 正确性 |
|----------|------|--------|
| 销售明细→生成工单 | 只生成1张成品工单 | ❌ 不适用于多级BOM |
| 履约助手→安排生产 | 自动展开BOM，生成全部工单 | ✅ 正确操作 |

### 三、工艺路线填写规则
| 产品类型 | 工艺路线 | 后果 |
|----------|----------|------|
| 原材料（外购） | 不填，保持空白 | 如果填了，系统会误以为要生产 |
| 半成品/成品（自制） | 必须填 | 如果不填，生成工单时会漏掉 |

### 四、多仓库管理核心规则
| 规则 | 说明 |
|------|------|
| 报工页面不选仓库 | 系统根据工序的“所属仓库”自动扣减 |
| 工序绑定仓库 | 3楼工序绑3楼仓，7楼工序绑7楼仓 |
| 成品分开编码 | 同一产品分车间生产，建议建两个成品编码 |
| 自定义事件分开配 | 3楼和7楼的包装工序分别配置事件 |

### 五、成品入库触发点
成品“5.5按摩弹力球-成品”的投料工序必须设置为对应车间的“入外箱”工序，只有入外箱报工才会触发成品自动入库。

### 六、部分委外+部分自制的核心原则
| 原则 | 说明 |
|------|------|
| 原工单不动 | 注塑、组装、包装按原计划做1000个 |
| 新建委外工单 | 独立管理那500个喷漆外协 |
| 账分开算 | 本厂工资按本厂报工算，外协加工费按委外单据算 |
| 进度条不重要 | 账对才是核心，进度条显示50%是真实的 |
| 不合并产出 | 委外产出不要手动合并进原工单，会歪曲工资核算 |

### 七、委外工废与料废区分
- 工废（外协责任）：不计加工费，可向供应商索赔。
- 料废（我方责任）：正常计价，我方承担损失。

## 第十二部分：常见问题

**Q：销售订单35箱，为什么白盒工单是840个？**
A：因为BOM中白盒的“单位用量”设置为24。工单数量 = 35箱 × 24 = 840个。

**Q：BOM单位用量在哪里设置？**
A：进入「基础数据」→「物料清单」→编辑对应BOM→在子件列表中找到“单位用量”字段→填写数值→保存。

**Q：为什么销售订单只生成了1张工单而不是全部？**
A：因为你点的是“销售明细→生成工单”。要实现多级BOM自动拆解，必须走“履约助手→安排生产”路径。

**Q：报工页面为什么不能选仓库？**
A：因为系统采用“报工即扣料”的自动逻辑，仓库由工序的“所属仓库”决定，不需要工人手动选。

**Q：3楼和7楼包装车间怎么分开管理库存？**
A：创建两个独立仓库，创建两组独立工序，将工序的“所属仓库”分别绑定到对应仓库。同一产品建议建两个成品编码。

**Q：同一个订单两个包装楼层都做怎么弄？**
A：在履约助手里把订单拆成两张工单，一张选3楼的成品编码，一张选7楼的成品编码，各自派给对应车间。

**Q：成品编码分开是什么意思？**
A：同一个产品在两个车间生产，需要在系统里建两个不同的产品档案（两个编码），各自绑定各自的工序和仓库。

**Q：报工数配比怎么用？**
A：用于工人按“个”报工但系统按“箱/盒”计算的场景。

**Q：部分委外+部分自制怎么操作？**
A：原工单不动，新建一张只包含委外工序的工单，数量填需要委外的部分。两张工单并行，账分开算。

**Q：改了原工单喷漆计划数，会影响后面包装工序吗？**
A：不会影响包装工序的计划数，但需要测试包装工序能否在喷漆报满后正常启动。建议先用小测试工单验证。

**Q：把委外产出合并到原工单喷漆产出里，会影响核算吗？**
A：会。系统会把委外产出算成本厂工人的计件工资，歪曲工资核算，同时外协加工费会丢失单据支撑。

**Q：委外需求是怎么生成的？**
A：当工单执行到标记为“委外”的工序时，系统会自动在「委外管理」→「委外需求」中生成一条记录。

**Q：采购需求是怎么生成的？**
A：在「履约助手」中点击「生成采购需求」，系统根据BOM计算原料用量，核对当前库存，自动生成采购建议清单。

**Q：客户档案在哪里维护？**
A：进入「基础数据」→「客户」→「创建客户」。

**Q：设备档案怎么用？**
A：进入「基础数据」→「设备」→「创建设备」，设备可与工单、报工模块关联。

**Q：外协厂需要安装软件吗？**
A：不需要。外协厂通过微信小程序链接即可查看任务、反馈完工。

**Q：报工后发现填错了怎么办？**
A：管理员可在后台「报工」模块批量修改。工单结束后数据锁定。
