# 黑湖小工单旗舰版（含委外管理）从0到1完整操作手册

* **适用版本**：黑湖小工单旗舰版（含销售管理、采购管理、委外管理）
* **工厂类型**：TPE/TPR软胶解压玩具（捏捏乐+电子配件）生产工厂
* **产品案例**：彩虹捏捏乐（红/黄/蓝三色混装，内置电子配件，5000套，美国客户外贸订单）
* **完整生产工艺**：
  * **注塑（含拌料）**：SEBS7561 + 15#白油 1:4泡油 → 加色粉4.2g/1kg泡好的料 → 注塑产出各色皮和各色盖子
  * **组装（3个独立工序）**：罐粉（3g填充粉料）→ 装电子配件 → 粘盖子（用注塑的盖子）
  * **移印**（只印皮，不印盖子）
  * **喷漆**（委外）
  * **填充**：麦芽糖浆45g
  * **包装**：吸塑 → 装PET → 入彩盒 → 入箱
* **核心模式**：**报工即扣料** —— 工人报工提交良品数量的那一刻，系统自动完成产量统计、物料库存自动扣减、计件工资自动累积，全程无需人工干预。
* **工单生成机制**：销售订单通过「履约助手」→「安排生产」触发系统自动展开BOM，工单数量 = 销售订单数量 × BOM单位用量。
* **目标读者**：系统小白，从0到1上线。

## 第一部分：系统认知与核心逻辑

### 一、工单数量计算规则（核心！）

这是理解系统最关键的规则，请务必先看明白：

**工单数量 = 销售订单数量 × BOM中该子件的单位用量**

**举例说明**：
* **销售订单**：450件（每件 = 1个外箱，内含2个内箱，每箱12个产品，共24个产品）
* **BOM中“红色皮”的单位用量** = 12个/件
* **系统自动生成工单**：450件 × 12个/件 = 5,400个红色皮工单
* **BOM中“黄色皮”的单位用量** = 12个/件
* **系统自动生成工单**：450件 × 12个/件 = 5,400个黄色皮工单

> ⚠️ **关键理解**：销售订单填的是“成品件数”（450件），子工单数量由BOM中的“单位用量”自动计算得出。不是必须把销售订单改成5400，而是确保BOM里的单位用量设置正确。

### 二、系统核心逻辑

销售订单通过「履约助手」→「安排生产」触发系统自动展开BOM，根据BOM单位用量自动计算所有子件的需求数量，一键生成全部半成品和成品工单。

## 第二部分：第一天——基础数据配置（一次性工作）

> ⚠️ **配置前必读：核心规则**
> 
> * **规则一：BOM单位用量决定工单数量**
>   * BOM中每个子件的“单位用量”告诉系统：每生产1件成品，需要消耗多少个该子件。
>   * 销售订单数量 × 单位用量 = 该子件的工单生产数量。
>   * 示例：450件成品 × 12个红色皮/件 = 5,400个红色皮工单。
> * **规则二：产品的“工艺路线”字段**
>   * 原材料（外购）：不填，保持空白。
>   * 半成品（自制）：必须填。
>   * 成品（自制）：必须填。
> * **规则三：外协工序需在工序设置中标记“委外”**
> * **规则四：产品属性决定采购需求**
>   * 外购（原材料、包材）：系统在“生成采购需求”时会自动计算这些物料的需求量。
>   * 自制（半成品、成品）：系统不会生成采购需求，而是生成生产工单。

* **罐粉不良**：克重不准（偏离3g）、漏粉
* **装电子配件不良**：配件装反、线路脱落
* **粘盖不良**：胶水溢出、盖子歪斜
* **移印/喷漆不良**：偏位、流油、颗粒、划伤
* **填充不良**：克重不准（偏离45g）、漏液
* **包装不良**：吸塑破损、彩盒折痕、装箱错误
* **委外不良**：工废（外协责任）、料废（我方责任）

## 第四部分：自定义事件配置——报工联动库存

### 一、什么是自定义事件？

自定义事件是黑湖小工单实现“报工联动库存”的核心配置工具。它的本质是：当某个操作发生（如工人报工）时，系统自动执行另一个操作（如生成入库单或出库单）。

**配置逻辑**：触发条件 + 触发动作 → 执行动作

* **触发条件**：系统判断“谁触发了这个规则”。比如 `${任务.工序名称} == '注塑（含拌料）'` 表示“当工人在'注塑（含拌料）'这个工序报工时”。
* **触发动作**：系统判断“发生了什么操作”。比如“新增数据”表示工人提交了新的报工记录。
* **执行动作**：系统应该做什么。比如“按工单用料清单生成入库记录”表示“把BOM里对应的物料增加库存”。

### 二、配置步骤

1. 登录系统，进入「生产管理」→「报工」→「自定义事件」
2. 点击「新建事件」
3. 按以下配置表填写，点击保存：

| 配置项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **事件名称** | 给规则起名 | 注塑报工半成品自动入库 |
| **触发表单** | 监控哪个模块的数据变化 | 任务（报工记录属于任务下） |
| **状态** | 是否启用 | 启用 |
| **触发事件类型** | 监控什么类型的变化 | 数据变更 |
| **触发事件动作** | 监控什么具体操作 | 新增数据 |
| **触发条件** | 判断规则是否触发的条件 | `${任务.工序名称} == '注塑（含拌料）'` |
| **执行事件类型** | 执行什么类型的操作 | 数据变更 |
| **执行表单** | 执行操作针对哪个表单 | 入库单 或 出库单 |
| **执行事件动作** | 执行什么具体操作 | 新增数据 |
| **执行动作** | 具体执行什么动作 | 按工单用料清单生成入库记录 |

> ⚠️ **关键提醒**：触发条件里的工序名称必须和系统里「基础数据」→「工序」里定义的名称完全一致，包括空格、括号、标点符号，否则规则不会被触发。

### 三、判断用入库单还是出库单

| 场景 | 执行表单 | 举例 |
| :--- | :--- | :--- |
| **该工序产出物料（库存增加）** | 入库单 | 注塑产出半成品、入箱产出成品 |
| **该工序消耗物料（库存扣减）** | 出库单 | 罐粉消耗填充粉料、包装消耗包材 |

### 五、后期自己增加和修改的方法

#### 方法一：复制修改（推荐）

2. 找到一条已配置好的事件，点击「复制」

   * 触发条件：`${任务.工序名称} == '新工序名'`

   * **触发事件类型**：数据变更
   * **触发事件动作**：新增数据
   * **触发条件**：`${任务.工序名称} == '你的工序名称'`
   * **执行事件类型**：数据变更
   * **执行表单**：入库单/出库单（根据场景选择）

4. 保存即可。

### 六、常见问题排查

| 问题 | 可能原因 | 解决方法 |
| :--- | :--- | :--- |
| **报工后库存没变化** | 触发条件里的工序名称和系统定义不一致 | 去「基础数据」→「工序」里确认准确名称 |

## 第九部分：常见问题

**Q：销售订单450件，为什么红色皮工单是5,400个？**  
A：因为BOM中红色皮的“单位用量”设置为12。工单数量 = 450件 × 12 = 5,400个。

**Q：BOM单位用量在哪里设置？**  
A：进入「基础数据」→「物料清单」→编辑对应BOM→在子件列表中找到“单位用量”字段→填写数值→保存。

**Q：如果看到子工单数量是450而不是5,400，怎么办？**  
A：说明BOM中该子件的“单位用量”被设成了1。去「物料清单」中找到对应BOM，把单位用量改成实际值即可。

**Q：采购需求里的数量是怎么算出来的？**  
A：采购需求数量 = 销售订单数量 × BOM单位用量。系统会自动展开所有层级计算。例如：450件 × 12个/件 × 0.01kg/个 = 54kg。

**Q：为什么销售订单只生成了1张工单而不是全部？**  
A：因为你点的是“销售明细→生成工单”。要实现多级BOM自动拆解，必须走“履约助手→安排生产”路径。

**Q：成品为什么在“入箱”时才自动入库？**  
A：BOM中成品“三色套装”的投料工序设置为“入箱”，只有入箱报工才触发成品自动入库。如果设置成更早的工序，产品还没装完箱就被当成成品了。

**Q：报工联动库存的触发条件是什么？**  
A：BOM用量标准必须准确，且投料工序配置正确。工人提交报工的那一刻，系统自动按BOM折算物料消耗并更新库存。

**Q：外协厂需要安装软件吗？**  
A：不需要。外协厂通过微信小程序链接即可查看任务、反馈完工，无需安装任何APP，不占用付费账号名额。

**Q：报工后发现填错了怎么办？**  
A：管理员可在后台「报工」模块批量修改。工单结束后数据锁定。

系统的逻辑是：报工数量 = 工序处理的对象数量。对于“入彩色PET盒”这道工序，它的处理对象是“成品”，所以计划数是450件（每一件成品需要经过这道工序一次）。

但在实际车间里，工人的操作是：一个一个地把产品装进PET盒，一共要装10,800个（450件 × 24个/件）。

这两者说的是同一件事，只是计量单位不同。

✅ 解决方案：用“报工数配比”解决
黑湖小工单支持在工序上设置“报工数配比”，让工人的报工数量和系统的计划数自动换算。

操作路径：进入「基础数据」→「工序」→ 编辑“入彩色PET盒”工序 → 找到“报工数配比”字段。

设置方法：把报工数配比设置为 24。

设置后的效果：

场景	工人报工	系统换算	工单进度
工人装了24个	报工24个	24 ÷ 24 = 1件	进度+1件
工人装了240个	报工240个	240 ÷ 24 = 10件	进度+10件
工人装了全部10,800个	报工10,800个	10,800 ÷ 24 = 450件	进度100%，工单完成
这样，工人可以按实际动作（一个一个装）来报工，系统会自动把数量换算成“件数”，工单进度显示也是正确的450件。

📋 同理设置其他包装工序
按你的包装规格（每件成品 = 24个产品、2个内箱、1个外箱），各工序的报工数配比设置如下：

工序	报工数配比	说明
入彩色PET盒	24	工人每装24个，系统记为1件成品
入内箱	2	工人每装2个内箱，系统记为1件成品
入外箱	1	工人每装1个外箱，系统记为1件成品（无需换算）
💡 配置后的完整效果
工人操作不变：还是扫码、一个一个装、按实际数量报工

系统自动换算：报工数配比自动把“个”换算成“件”

工单进度正确：进度条按“件”显示，最终100%时表示450件完成

工资计算正确：系统会按工人实际报工数量（如10,800个）乘以单价计算工资

📝 操作步骤总结
进入「基础数据」→「工序」

找到“入彩色PET盒”工序，点击编辑

在“报工数配比”字段填入 24

保存

对“入内箱”工序重复操作，填入 2

重新安排生产，生成新的工单验证

这样设置后，工人可以按实际动作报工，系统也能正确追踪工单进度和计算工资，两边都不矛盾了。
